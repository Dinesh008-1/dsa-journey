## Extended Moore's Voting Algorithm (Majority Element II)

## 1. Trigger Clues
- Find elements appearing more than ⌊n/3⌋ times.
- There can be at most two majority elements.
- Need O(n) time and O(1) auxiliary space.
- Generalization of Moore's Voting Algorithm.
## 2. Core Intuition

Cancel groups of three distinct elements.

Since we are looking for elements appearing more than n/3 times, removing three distinct elements at a time cannot completely eliminate a valid majority element.

Therefore:
- Maintain two candidate elements.
- Maintain two frequency counters.
- If both candidates are occupied and a different element appears, decrement both counters.
- At the end, the remaining candidates are only potential answers.
- Perform a second pass to verify their actual frequencies.
## 3. Java Template
```java
int c1 = 0, c2 = 0;
int ans1 = 0, ans2 = 0;

// First pass: Find potential candidates
for (int num : nums) {
    if (c1 == 0 && num != ans2) {
        ans1 = num;
        c1++;
    } else if (c2 == 0 && num != ans1) {
        ans2 = num;
        c2++;
    } else if (num == ans1) {
        c1++;
    } else if (num == ans2) {
        c2++;
    } else {
        c1--;
        c2--;
    }
}

// Second pass: Verify candidates
c1 = 0;
c2 = 0;

for (int num : nums) {
    if (num == ans1) c1++;
    else if (num == ans2) c2++;
}

List<Integer> ans = new ArrayList<>();

if (c1 > nums.length / 3) ans.add(ans1);
if (c2 > nums.length / 3) ans.add(ans2);

return ans;
```

## 4. Complexity
- Time: O(n) — Two passes through the array.
- Auxiliary Space: O(1) — Two candidates and two counters. (Output list excluded.)
## 5. Common Mistakes
- Assuming there can be three majority elements.
- Forgetting to decrement both counters when encountering a third distinct element.
- Treating potential candidates as confirmed answers.
- Forgetting the second pass to verify actual frequencies.
- Not checking num != ans2 and num != ans1 when filling empty candidate slots.
- Using >= n/3 instead of strictly > n/3.
